\# ADR-0002. Вибір стратегії баз даних (СУБД)\[cite: 1]



\## Статус\[cite: 1]

Accepted\[cite: 1]



\## Контекст (Context)\[cite: 1]

Система працює з двома кардинально різними типами даних. Перший тип — транзакційні бізнес-дані (клієнти, замовлення, маршрутні листи), які вимагають суворої цілісності (ACID). Другий тип — часові ряди (Time-Series дані), тобто мільйони записів GPS-координат, швидкості та рівня палива, що надходять щосекунди і потребують швидкого запису та агрегації за часом\[cite: 1].



\## Рішення (Decision)\[cite: 1]

Прийнято рішення використовувати підхід \*\*Polyglot Persistence (Гібридне зберігання)\*\*:\[cite: 1]

1\. \*\*PostgreSQL\*\* — як основна реляційна база для зберігання бізнес-сутностей (користувачі, платежі, замовлення).

2\. \*\*TimescaleDB\*\* (розширення поверх PostgreSQL) або спеціалізована Time-Series DB (наприклад, \*\*InfluxDB\*\*) — для зберігання телеметрії та геолокаційних даних пристроїв IoT.



\## Розглянуті альтернативи (Alternatives Considered)\[cite: 1]

\- \*\*Єдина реляційна БД (лише PostgreSQL):\*\*\[cite: 1]

&#x20; - \*Переваги:\* Проста інфраструктура, єдина точка резервного копіювання.

&#x20; - \*Недоліки / Чому відхилено:\* Стандартні таблиці швидко деградують у продуктивності (Performance) при вставці мільярдів записів телеметрії; складність агрегації часових вікон.

\- \*\*Єдина NoSQL БД (наприклад, MongoDB):\*\*\[cite: 1]

&#x20; - \*Переваги:\* Гнучка схема, легко масштабується горизонтально.

&#x20; - \*Недоліки / Чому відхилено:\* Відсутність надійних ACID-транзакцій для фінансових операцій та розрахунків вартості доставки, що є критичним для бізнесу.



\## Наслідки (Consequences)\[cite: 1]

\- \*\*Позитивні наслідки:\*\*\[cite: 1]

&#x20; - Атрибути якості: Максимальна продуктивність (Performance) як для складних реляційних запитів, так і для потокового запису геоданих\[cite: 1].

&#x20; - Ефективне управління ресурсами бази (Resource Utilization) за рахунок стиснення старих часових рядів.

\- \*\*Негативні наслідки / Компроміси (Trade-offs):\*\*\[cite: 1]

&#x20; - Ускладнення адміністрування інфраструктури (DevOps доведеться підтримувати дві різні СУБД)\[cite: 1].

&#x20; - Складність консистентного бекапування даних між двома системами.
