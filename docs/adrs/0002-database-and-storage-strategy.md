\# ADR-0002. Вибір стратегії баз даних (СУБД)



\## Статус

Accepted



\## Контекст (Context)

Система працює з двома кардинально різними типами даних. Перший тип — транзакційні бізнес-дані (клієнти, замовлення, маршрутні листи), які вимагають суворої цілісності (ACID). Другий тип — часові ряди (Time-Series дані), тобто мільйони записів GPS-координат, швидкості та рівня палива, що надходять щосекунди і потребують швидкого запису та агрегації за часом.



\## Рішення (Decision)

Прийнято рішення використовувати підхід \*\*Polyglot Persistence (Гібридне зберігання)\*\*:

1\. \*\*PostgreSQL\*\* — як основна реляційна база для зберігання бізнес-сутностей (користувачі, платежі, замовлення).

2\. \*\*TimescaleDB\*\* (розширення поверх PostgreSQL) або спеціалізована Time-Series DB (наприклад, \*\*InfluxDB\*\*) — для зберігання телеметрії та геолокаційних даних пристроїв IoT.



\## Розглянуті альтернативи (Alternatives Considered)

\- \*\*Єдина реляційна БД (лише PostgreSQL):\*\*

&#x20; - \*Переваги:\* Проста інфраструктура, єдина точка резервного копіювання.

&#x20; - \*Недоліки / Чому відхилено:\* Стандартні таблиці швидко деградують у продуктивності (Performance) при вставці мільярдів записів телеметрії; складність агрегації часових вікон.

\- \*\*Єдина NoSQL БД (наприклад, MongoDB):\*\*

&#x20; - \*Переваги:\* Гнучка схема, легко масштабується горизонтально.

&#x20; - \*Недоліки / Чому відхилено:\* Відсутність надійних ACID-транзакцій для фінансових операцій та розрахунків вартості доставки, що є критичним для бізнесу.



\## Наслідки (Consequences)

\- \*\*Позитивні наслідки:\*\*

&#x20; - Атрибути якості: Максимальна продуктивність (Performance) як для складних реляційних запитів, так і для потокового запису геоданих.

&#x20; - Ефективне управління ресурсами бази (Resource Utilization) за рахунок стиснення старих часових рядів.

\- \*\*Негативні наслідки / Компроміси (Trade-offs):\*\*

&#x20; - Ускладнення адміністрування інфраструктури (DevOps доведеться підтримувати дві різні СУБД).

&#x20; - Складнощі узгодженого резервного копіювання даних між двома системами.
