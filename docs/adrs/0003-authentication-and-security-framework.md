\# ADR-0003. Вибір стратегії автентифікації та безпеки\[cite: 1]



\## Статус\[cite: 1]

Proposed\[cite: 1]



\## Контекст (Context)\[cite: 1]

У логістичній системі є два типи акторів, які потребують доступу: "людські" користувачі (клієнти на вебпорталі, водії в мобільному додатку, диспетчери) та IoT-пристрої (трекери на транспорті). Використання єдиного механізму для обох груп є небезпечним та неефективним через різну природу взаємодії з системою\[cite: 1].



\## Рішення (Decision)\[cite: 1]

Прийнято рішення використовувати \*\*гібридну стратегію автентифікації\*\*:\[cite: 1]

1\. \*\*Для користувачів (Web/Mobile):\*\* Використання стандарту \*\*OAuth 2.0 / OpenID Connect (OIDC)\*\* на базі готового Identity Provider (наприклад, Keycloak). Це дозволить зручно керувати ролями (RBAC) та підтримувати SSO.

2\. \*\*Для IoT-трекерів (Machine-to-Machine):\*\* Використання \*\*Mutual TLS (mTLS) з X.509 сертифікатами\*\*. Кожен фізичний пристрій отримує унікальний сертифікат для підключення до MQTT-брокера або API-шлюзу.



\## Розглянуті альтернативи (Alternatives Considered)\[cite: 1]

\- \*\*Базова автентифікація (Basic Auth) для IoT:\*\*

&#x20; - \*Переваги:\* Легко імплементувати на дешевих мікроконтролерах.

&#x20; - \*Недоліки / Чому відхилено:\* Вкрай низький рівень безпеки. Витік одного логіна/пароля компрометує пристрій.

\- \*\*JWT (JSON Web Tokens) для IoT-пристроїв:\*\*\[cite: 1]

&#x20; - \*Переваги:\* Єдиний стандарт токенів для людей і пристроїв.

&#x20; - \*Недоліки / Чому відхилено:\* Складність безпечного зберігання Secret Key на апаратному пристрої. Трекерам складно керувати життєвим циклом токенів (Refresh).



\## Наслідки (Consequences)\[cite: 1]

\- \*\*Позитивні наслідки:\*\*\[cite: 1]

&#x20; - Атрибути якості: Найвищий рівень безпеки (Security) та автентичності (Authenticity)\[cite: 1].

&#x20; - Неможливість підміни трекера зловмисником без фізичного доступу до приватного ключа пристрою (захист від GPS Spoofing).

\- \*\*Негативні наслідки / Компроміси (Trade-offs):\*\*\[cite: 1]

&#x20; - Інфраструктура відкритих ключів (PKI) для генерації та ротації X.509 сертифікатів додає значного навантаження на етапі розгортання (Provisioning) нових пристроїв на складі\[cite: 1].
